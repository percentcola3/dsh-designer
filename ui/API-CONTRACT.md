# Workbench UI integration contract

Entry: `Workbench({ctx,t?,Canvas,api,onExit,legacy?})`, default and named export, ESM JSX, `react` external. No client singleton imports. All business actions use `api(action,args)` returning value or throwing Error with code/details. UI-only view state uses React and persisted `workspace.state.*`.

## Read-only diagnostics

`diagnostics.run({projectId?,categories?:['environment','generation','assets','knowledge']})` returns schemaVersion1/readOnly, exact scope, summary, bounded checks with evidence/recommendation/guideId, guideTopics and honest limits. Default is all applicable categories. Owner GUI may inspect capped library metadata or one chosen project. Global model without a frozen task gets environment/static guides only; project model uses its admitted Design/pages/bindings/references, never sibling contents. No shell/model/network/probe/index/write occurs. Missing evidence is unknown, not a successful configuration or visual-quality score.

`diagnostics.catalog()` returns seven progressive topics. `diagnostics.guide({topic,offset?,limit?})` returns text/offset/limit/total/nextOffset, limit<=12000. Project wrapper projectId is contextual and must match the task. Transport contextSessionId is resolved and removed by the owner ingress before the business service.

Global SettingsPanel now accepts api; global/project settings expand DiagnosticsPanel lazily. It supports filters, retry, healthy collapsed checks, explicit guide reads, <=7000-character sanitized copy prompt, and a real manual-copy fallback. Optional onAskAI must only populate an actual native draft; it is absent by default. Never route diagnosis to Designer homepage generation or silently send a message. Existing authorized improvements continue through scoped actions/CAS; diagnosis does not confer new authority.

## Adaptation

Workspace short action names follow WORKBENCH-PLAN. Lead adapter may prefix `workbench.*`. Source workflows always use `workbench.source.*`; external source code runtime uses `runtime.*` mapped to DeliveryService `source.*`. Git/export/share use their names. Errors are displayed, never inferred successful from lack of throw if action returns explicit failure.

- `state -> {projects,groups,systems,root}` and existing project/group create/update/delete/archive/restore.
- `workspace.open({projectId}) -> {project,projectRevision,designs,pages,files:[tree entries],documents?:{[pageId]:{html,tree,nodes,diagnostics,assetBase}}}`. Missing documents are loaded with existing `artboard.get`.
- `workspace.state.get/save({projectId,state?,expectedVersion?}) -> {state,version}`. State includes `tabs:Tab[]`, `activeTabId`, target, selection, references, designId, mode, device/custom viewport and navigation width/tab. File tab bodies and temporary URLs are stripped from view state; drafts own unsaved text. Restored resources are re-read and drafts take priority over fresh content.
- `file.read({projectId,fileId|path,offset?,limit?}) -> {fileId,path,type,mimeType,content,text,version,total,nextOffset,byteLength,url|previewUrl|downloadUrl,readonly?}`. Binary/image/PDF/media require scoped resource URL; not arbitrarily opened from local filesystem.
- `file.write({projectId,fileId,path,content,expectedRevision,expectedVersion}) -> {version,project?,projectRevision?}`; create/rename/move/copy/remove as WorkspaceService (move/copy destination key `to`; rename/move/delete-bytes include current `expectedVersion`). Source file operations also pass registered `sourceId` and project-relative path. Remove defaults unregister; `deleteFiles:true` is explicit UI checkbox.
- `file.reconcile({projectId,fileId|path,sourceId?,expectedProjectRevision,expectedVersion,mode:'adopt-external'|'keep-local'|'merge',content?})` is an explicit user action. The viewer blocks ordinary saving when externallyModified or draft conflict is present; a successful reconciliation is followed by a true file.read and draft.remove using the draft's own CAS. For external sourceId the Core preserves external/local candidates, validates writablePaths and uses FsVersion CAS on the actual working-tree path; adopt-external confirms metadata without changing original bytes. Returned source history can be read with sourceId/path/revisionId. The UI passes localContent as well, so restoring a historical candidate does not lose the currently buffered local draft.
- `draft.get/save/remove({projectId,resourceId,draft?,expectedVersion?}) -> {draft,version}`. File drafts `{content,view,mode,baseVersion}`; compose draft `{prompt,references,attachments}`. Save failure keeps tab; user can retry, keep, or explicitly discard.
- `binding.resolve({projectId,designId}) -> {effectiveBinding?}`; preview/set `{scope:'project'|'design',designId?,binding:{mode:'inherit'|'independent'|'none',systemId?,version?}}`. apply records scope; does not rewrite HTML. UI previews before set.
- `project.initialize` first initializes a new project with one Web Design and one real root `index.html` artboard, returning `{project,projectRevision,design,page,artboard,files,start}`. Existing/previously initialized workspaces are not given replacement designs. Initialization retries reuse stable initial identities and preserve preexisting entry bytes.
- `design.create` returns `{project,projectRevision,design,page,artboard}` and creates its initial root `design.folder/index.html`, `assets/README.md`, `css/style.css` and `js/main.js` (legacy styles/pages remain). The UI must reuse that initial page instead of immediately calling page.create again. `page.create` is for additional artboards at pages/.../index.html. `design.update/clone/delete/reorder` and `page.update/clone/delete/reorder` retain their existing CAS contracts; a design clone puts its first cloned page at its own root index. Reorder passes ids; page.clone can pass targetDesignId.
- `asset.import/replace({projectId,name,mimeType,bytesBase64,path?,fileId?,expectedRevision,expectedVersion?})`. Result includes file/fileId/path and project revision. External copies use asset.copy; downloads use returned URLs.
- `reference.resolve({projectId,reference}) -> {valid,status,message,file?,pageId?,...}`. Missing/stale references explicitly fail; never locate a similarly named object. `reference.create({projectId,directory:<absolute path>,label?})` is user-only and returns `{reference:{type:'directory',projectId,resourceId,rootPath,sourceVersion,label,readonly:true},readonly:true}`. It performs readonly resolution, not source registration. `reference.list/read({projectId,reference,path?,offset?,limit?,expectedVersion?})` supports exact admitted directory/project references; list is one level with at most 200 entries, read at most 12000 Unicode codepoints. Read offset/nextOffset are UTF-8 byte offsets; forward expectedVersion on subsequent file pages. Agent reads require the same valid readonly identity in task.refs and enforce canonical containment/private paths/host Fs. External project references retain fixed positive revision and the admitted overview hash. The @ menu can invoke directory selection or accept its absolute path, then add the returned readonly reference.
- `edit.apply({projectId,designId,pageId,operations,expectedRevision,expectedArtboardRevision,expectedFsVersion,allowUnlock?,summary}) -> {project?,document?,page?,html?,diagnostics}`. UI returns Promise and real response to Canvas; iframe messages never authorize edits.

## Complete packages, clipboard, built-in Git and SSH

All `package.*`, `sync.*` and `ssh.profile.*` actions are owner-only even when a model forges user options. Credentials never appear in response objects. The native file sandbox continues to apply; no operation grants new roots.

- `package.create({projectId,expectedRevision}) -> {package,manifest,project,projectRevision}` saves a real ZIP and returns the existing authenticated delivery download URL; `package.list/get({projectId,exportId?})` reads frozen artifacts. A portable snapshot includes raw page models, public project files and pinned self-contained systems, with bounded canonical paths, full SHA-256 index and `designer-project.json`; external sources, machine state, sessions and private content are excluded.
- `package.clipboard({projectId,kind:'project'|'html'|'png',expectedRevision?,exportId?,pageId?})` returns actual bounded content: project portable text with `DSH_PORTABLE_PROJECT_V1\n` prefix; raw HTML text; or verified PNG `bytesBase64`. Current-content reads require project CAS; frozen package / PNG reads use exportId. Client writes actual text or image/png ClipboardItem. Project text is not an OS ZIP file clipboard object. Bounds: 16 MiB clipboard; 4000 files / 32 MiB each / 128 MiB complete snapshot.
- `sync.get/status({projectId,fetch?}) -> {binding,capabilities,status,projectRevision}`. Status includes `head,remoteHead,branch,changes:[{path,status}],dirty,ahead,behind,conflicts,checkedAt,initialImportPending`. `fetch:true` and `sync.check` update remote tracking, never live files. `sync.detect` inspects only the project's own .git, does not climb to parent repositories or auto-bind.
- `sync.save({projectId,expectedRevision,repositoryUrl,branch,projectPath,author:{name,email},authProfileId?,autoCheck?,httpsToken?,clearHttpsToken?}) -> {project,projectRevision,binding,capabilities}`. Binding has `hasHttpsToken` only. HTTPS and SSH use an embedded JavaScript Git engine; no local git/ssh binary is required. Repository state is isolated by remote URL and branch inside the project private sync directory. Only projectPath's subtree is replaced; other repository files, trees and history remain untouched. `sync.unbind` keeps local project content and history.
- `sync.test/branches` accept draft repository/branch/auth fields, return explicit `reachable` and remote branch names, and do not persist the draft or alter configured remote refs.
- `sync.commit/pull/push/sync` require project CAS; commit and sync require message. All verify drafts and active AI work, use exact HEAD, fast-forward only and never force push. First pull/sync with existing remote content returns `SYNC_INITIAL_IMPORT_CONFIRMATION_REQUIRED`; only explicit confirmation resends the original arguments plus `allowInitialImport:true`. Missing project, simultaneous local/remote changes, divergence, stale metadata, auth and native permission failures remain visible. Imported files are appended under a new immutable local prefix, then metadata is published by CAS; old originals/history and local Session/grants/references remain. Stable logical paths/system mappings prevent physical import prefixes or local spec IDs causing false dirty status. Shared system import additionally needs native permission for the system library; project-only permission is never expanded.
- `ssh.profile.list/get/generate/import/remove/inspectHost/trustHost/test`: profile changes use exact `expectedRevision`; generate/import take name, host, port and username plus optional passphrase (import also privateKey). Public profiles expose publicKey, key fingerprint, trustedHost and hasPrivateKey, never secrets. inspectHost only obtains the host SHA256 fingerprint and a short-lived challenge. trustHost requires that exact challenge/fingerprint and revision; checking does not trust. Keys are held by native credentials and never written to ~/.ssh. Model actions cannot manage profiles or resolve internal transport credentials.

`ProjectSyncPanel({api,project,onChanged,onBeforeSync,registerGuard})` lives inside ProjectSettingsPanel. Draft guards participate in workspace close/exit protection; auto-check defaults off and, while enabled in the panel, fetches remote state every minute without committing/pulling/pushing. Successful import invalidates page/file caches before returning to the canvas. DeliveryPanel's onChanged refreshes project CAS after recording an export.

## Local zg knowledge libraries

The global knowledge page is a directory tree, with local and Git import, short progress/errors, search and originals. Rename/archive/project mounts live in a more menu. KnowledgePanel accepts {api,library,onRefresh,registerGuard,onPickDirectory?}; the optional picker only returns a source path, never changes the library root. No runtime/model setup or algorithm selectors are part of the main flow.

- Owner-only knowledge.import.local accepts path OR source projectId, optional name/knowledgeId/expectedRevision. knowledge.import.git accepts repositoryUrl, branch?, authProfileId?, private httpsToken?/httpsUsername? and target identity. Both return {job,knowledge}; knowledge.import.status/cancel use exact jobId. Jobs distinguish scanning/fetching/importing/cancelling from true completion; all saved originals remain on partial failure/cancel.
- Browser batches call knowledge.import.begin({knowledgeId,expectedRevision,source}) -> {knowledge,batchId}; raw upload query includes batchId, knowledgeId, expectedRevision, relativePath. Every successful file advances CAS; no index starts during the batch. knowledge.import.complete({knowledgeId,batchId,expectedRevision,failures?,cancelled?}) seals once and schedules one BM25 index. Cancellation uses complete(cancelled:true), never import.cancel, which belongs to asynchronous import jobs. Same relative paths update active documents while old original manifests/capabilities remain readable to owners.
- Native FTS-only indexing uses actual official Zvec scalar text fields and no vector schema. Defaults: backend=zvec-fts, vectorEmbedding=false, indexRequiresModel=false, modes=[bm25], model.required=false. No model cache, setup or network is needed. Old combined vector indexes remain compatible. Explicit unavailable vector modes return an honest mode error. DSH public chat interfaces are not represented as embeddings.
- FTS query without cache authority opens the immutable index readOnly with queryIsolation=read-only-index and no temporary writes. Existing native/task write grants may narrow a process to a single private UUID machine-cache root. Vector legacy indexes still require such an isolated snapshot. Native read-only/task read scope is never upgraded. Trusted nativePolicy/queryNativeScope comes only from Host authority, never model payload. workbench.status includeKnowledgeNativeProbe exercises fixed synthetic data through separate real write-scoped build and native-read-only query processes, then cleans its owned cache; no real KB data is read or modified by that diagnostic.
- Model actions remain only knowledge.search/read/resource.list over exact admitted {type:knowledge,projectId,resourceId:knowledge:k-id,knowledgeId,sourceVersion:<contentRevision>,label,readonly:true}. AI prepare performs real BM25, total context <=16k, path/line/sourceVersion citations and publication revalidation. Documents/comments are untrusted reference data; no reference grants writes. CRUD, indexing, imports, originals and project bindings remain owner-only.
- Owner state includes compact knowledge summaries; unavailable entries do not block other libraries. Content import/archive advances contentRevision and invalidates refs/index; rename/description only advances metadata revision. Originals max64 MiB/file, 2000 files/library; import max128 MiB total, projections max1 MiB/file and64 MiB corpus. UTF-8 and canonical path/hash/version checks remain enforced; binary/PDF/Office/images are original-only, with no OCR claim. Local sources remain read-only, no followed links or private/dependency files. Git only shallow fetch/readTree in an owned private bare mirror, no checkout/hooks/push; existing trusted SSH profile and current HTTP proxy are reused, never returned in metadata.
- GET/HEAD /api/designer/meta returns only version, transportVersion, sourceFingerprint, static capabilities and non-capability instanceId; no roots, account/model data or business state. It is no-store/nosniff without CORS. Business /api/designer retains native owner admission and exposes matching X-Designer-Version/X-Designer-Instance headers. workbench.status.server identifies the same activation for real-origin stale-backend diagnosis.

## Shared composer and Native Session ownership

`composer.prepare({projectId? ,sessionId?}) -> {sessionId,projectId?,projectRevision?}` is owner-only and never prompts a model. With projectId it prepares the actual project Session without changing project metadata; without projectId it creates a real ordinary draft Session. An explicitly supplied homepage sessionId must resolve to the same owned library record; it is reused across tab mounts and cannot claim an arbitrary Session.

`composer.adopt({projectId,sessionId,expectedRevision}) -> {project,sessionId,projectRevision}` is owner-only and binds a prepared homepage Session to one project, preserving Native model, permission and receipt ownership. Persisted identical bindings are idempotent; a foreign Session, second project, changed library or stale new-binding revision fails. Native receipt resolution always receives the real Agent/Session object, never a fabricated object containing an id.

Home and canvas use DesignerComposer. Root Surface supplies the standard `useSessionAccess(sessionId,action)` and `useRemoteAccess(action)` Hooks. The adapter retains the real Session and uses shared ModelDirectory, permissions projection/catalog/command, Native upload service and optional speech RPC. Core input slots are privately owned and are not redeclared. Remote permission-presets and speech namespaces require their own declared/scoped injection.

Project references are `{type:'project',referencedProjectId,resourceId:'project:<source-id>',sourceVersion:<source-project-revision>,projectId?:<target-owner-id>,label?}`. The outer reference.resolve projectId remains the target owner. Only this explicit type may read a different project, and only a bounded public readonly overview is admitted. context.read requires the frozen exact namespace/version/hash; references do not enlarge write grants. Current file selection freezes the actual reference.resolve sourceVersion/FsVersion.

Design-scoped system changes call `binding.set({projectId,designId,expectedRevision,binding:{mode:'independent',systemId,version}})` or `{mode:'none'}`. Home design.create records the selected fixed version before ai.run. Neither selector invokes binding.apply or rewrites existing content.

## AI

`ai.run({projectId,activeDesignId,designId?,artboardId?,mode,prompt,target,frozenTarget,references,attachments,binding,effectiveBinding,allowedPaths?,targetConfirmation?})`. `activeDesignId` is the current canvas Design, independent of the requested target. The default writable target remains this Design after successful submission or deselection; an explicitly chosen readonly mode remains readonly. Explicit local-file targets use fileId/path plus allowedPaths:[exactPath]. Registered external source-file targets are readonly in this protocol; references never grant sourceWrite. Legacy internal admissions without activeDesignId retain their compatibility protocol.

Cross-Design targets, project scope, explicit public files outside the active Design, or an unambiguous named Design write instruction return `TARGET_CONFIRMATION_REQUIRED` before Session creation/task persistence. Details contain `{token,expiresAt,projectId,projectRevision,activeDesignId,requestedTarget,proposedTarget,reason,message}`. The dialog resends the identical original payload with only `targetConfirmation:token` added. Never replace its target with proposedTarget on the client. Any change to draft, references, attachments, target, active Design or project revision invalidates the pending confirmation. Cancel preserves the compose draft. Confirmation is limited to the exact request and project, expires in ten minutes, and cannot authorize external knowledge writes. Success returns `{accepted,sessionId,target,effectiveBinding,effectiveBindingsByDesign}`; use the final target for history and retries.

All Designs in one project retain the same native Session and conversation/compose draft. Changing the active Design resolves that Design's binding without creating another Session; stale binding replies are ignored. Each admitted task freezes its final target binding, and project-wide work freezes effectiveBindingsByDesign separately. Later canvas switches do not retarget an in-flight task. Native file-operation policies intersect the canonical project directory with native grants, strip other writable roots and keep readonly readonly; canonical Design boundaries reject aliasing into sibling Designs or external directories.

`ai.status` returns `{running,queue,pendingInput,taskRecoveryError,error?,sessionId,messages:[{id?,role,text|content,requestId?,references?,target?}],request?:{sessionId,requestId,generation,source,terminalReason?,...}}`. It exposes the latest native queue/user RPC lifecycle using exact request/turn identity, with a same-Session project task anchor only as fallback. generation is requested/running/completed/cancelled/failed/incomplete/unknown; !running alone does not prove completion. Native completed means the request ended, while source output coverage and review remain separate. Returns up to60 recent messages. DSH Session subscription triggers status reads, with a one-second fallback while running. AIPanel keeps the same instance across dock/sidebar changes; layout preference and independent widths use the dedicated machine key dsh-designer:canvas-conversation:1 and never enter AI payloads.

`legacy` can provide `{ImportDialog,createImportDialog(apiOverride),openFullChat(sessionId),getAIState,subscribeAI(projectId,fn),onInspect}`. Existing `ctx.sessions.refresh/retain` and `ctx.uiWorkspace.openSession` are compatibility fallback. Import override adds designId/target but does not steal current content tab. Preserve legacy import CSS at integration.

## Source workflows

Uses exact SourceWorkflows `workbench.source.plan/select/capture/import/read/compare/refreshPreview/applyRefresh/generate/rebuild` contract from source-workflows-notes.md. UI owns sync zoom/scroll and circle selection. Original snapshots, editable generation, visual checks and interaction checks remain distinct states. No account credential fallback is fabricated.

## Raw upload and attachment viewers

`api.upload(file,{projectId?,composerSessionId?,contextSessionId?,purpose:'attachment'|'asset'|'system-package',name,mediaType,designId?,expectedRevision?,fileId?,path?,expectedVersion?,replace?,type?})` sends an actual File/Blob to `/api/designer/upload`. The fallback helper calls that raw route directly; it does not base64-encode large bodies. Attachment responses are original Session receipts `{receiptId,file|image,receivingSessionId}`; AIPanel adds only an optional display label and sends the receipts directly in attachments[]. Asset responses use Core import/replace shape and update project cache. Replace also invalidates rendered dependencies and refreshes its open resource tab.

`attachment.get({projectId,receiptId}) -> {name,mimeType,byteLength,readonly:true,previewUrl?,downloadUrl?,content?}` is the readonly resource-tab adapter requested from Lead. It must resolve the project's actual `project.aiSessionId || designer-${projectId}` Session receipt with its real Agent/Session object and generate safe capabilities, never accept caller paths. Restored attachment tabs re-fetch that adapter. The endpoint is a Host integration task, and explicit errors remain visible until it is wired.

## Delivery

Runtime actions use `runtime.register/list/update/unregister/start/status/logs/stop/map`, mapped to DeliveryService `source.*`. Source register accepts directory/name/command/port/url. Logs use stdoutOffset/stderrOffset. Runtime tags use actual run.url. Git status/diff/branches read only; commit exact selected paths/message/expectedHead; pull/push/checkout separately confirmed by user. Export create format/scope/page revisions/background/editorMarks and download from export.get. Share uses scope/exportId/project and share CAS revisions. No automatic push, publish, or command start.

## Canvas

Props exactly plan plus ctx/onInspect optional compatibility. selection `{pageId,nodeIds,bounds?,objects}`. onChange is asynchronous. onReference accepts element/region refs with stable IDs. Active tab carries selected page/view/camera/scene; Canvas editing and preview share the same content tab. Device viewport is passed in viewState and UI should coordinate custom viewport with Canvas implementation.
